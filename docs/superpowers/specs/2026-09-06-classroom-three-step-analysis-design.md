# 課堂三步命盤分析設計

日期：2026/09/06。狀態：設計方向已獲同意；本書面規格待使用者確認，尚未實作。

## 1. 目標與已同意的方向

使用者要求把 2026/07/01～09/02 的課程整成《上課筆記整理.md》，並讓一般命盤依「取格局 → 辨日主強弱 → 判喜忌」分析，不只顯示課堂命例。

採用獨立課堂分析，顯示於既有「上課內容」，保留原本用神分析與量化五行力。規則衝突或條件不足時提供候選與理由，不強判唯一答案。使用者已回覆「繼續」同意此方向，並要求依任務難度分派模型。

本文定義首版的可交付範圍及不能自動斷定的界線。課堂規則是本課派方法；程式正確執行不等於現實預測能力獲得驗證。

## 2. 現況與修改邊界

目前工作樹已有未提交的課堂功能修改，不能以 HEAD 的舊版本覆蓋它們。

- `src-tauri/src/bazi.rs`：排盤、直輸四柱、普通取格及回應型別。
- `src-tauri/src/quant_model.rs`：量化模型、互動、特殊格、`build_lesson_content` 及既有課例註解。
- `src/components/CourseContentPanel.vue`：顯示課例候選與 App 原值。
- `src/types/bazi.ts`：前後端課堂回應契約。
- `src/App.vue`：桌面與精簡分析版皆已使用 CourseContentPanel。

保留原有 `geJu`、量化總分、逐柱分數、原用神、特殊格、大運計分、既有精確課例和不匹配機制。新增分析不得修改原始四柱、藏干表或用新結果反向餵回舊模型。

不新增全站狀態、不引入線上 LLM、不要求 API key、不上傳使用者命盤。模型分工僅用於開發，App 執行時是本地、可重現的規則運算。

## 3. 首版範圍

### 包含

1. 日期排盤及直輸四柱兩個入口都產生三步課堂結果。
2. 一般普通格的月令／藏干／透干理由。
3. 得時、得勢、得地、印當令支持、剋洩耗與互動的結構化證據。
4. 根據課堂強弱候選及實際十神分布提出普通格取用分支。
5. 用神方向、喜神、忌神、有條件方向按方案分開，不合併成單一元素列表。
6. 特殊格適用性、跨課次差異、通關及調候的有限條件說明。
7. 課程來源、工程近似標記、待定原因與 App 原值逐項比較。

### 不包含

- 全面重建量化模型、任意新分數或老師未給定的有效根權重。
- 自動歲運轉格、濕土／回剋強度重算、出生地／時區設計。
- 新增「課程規則庫」畫面或顯示全部未命中規則。
- 疾病、死亡、自傷、事故、婚姻成敗、投資收益、人格或人生等級的自動斷語。
- 將未核對來源命例作測試正例，或藉修改出生資料符合故事。

## 4. 架構與資料流

新增專用 `src-tauri/src/lesson_analysis.rs`，避免繼續擴大 quant_model.rs 的課堂規則區。模組只讀輸入，不修改舊模型資料。

```text
排盤／直輸四柱
    ↓
既有排盤事實、普通格、原量化模型與本命互動
    ↓（只讀轉接）
LessonFacts
    ├─ 第一步：普通格＋特殊格審查狀態
    ├─ 第二步：課堂強弱候選＋限制
    └─ 第三步：以上兩步＋事實 → 條件式喜忌方案
    ↓
lessonContent.threeStepAnalysis
    ↓
上課內容：三步分析 → 命例補充
```

第一步先列格局；特殊格是否可用仍須查第二步的根氣／旺勢。實作使用無循環的計算：整理事實 → 普通格與特殊格候選 → 強弱 → 確認適用範圍 → 喜忌。UI 仍按三步顯示。

同一四柱在兩個入口應有相同的課堂事實、強弱與喜忌候選。生日、性別、原量化參照字串不得改變本命課堂判別；不同入口的來源說明可不同。

## 5. 回應契約

`QuantLessonContent` 新增可選 `threeStepAnalysis`。新後端的兩個入口均提供；前端遇到舊資料沒有該欄時顯示「此結果尚無三步分析」，保留舊課例，不能偽造結果。

`LessonThreeStepAnalysis` 包含：

- `version`：固定首版識別 `classroom-2026-09-v1`。
- `status`：`candidate`、`conditional` 或 `insufficient`，表示領域結論狀態，而非程式是否執行。
- `facts`：四柱、日主／五行、月令、藏干、透干、根氣位置、五類十神分布。
- `pattern`：普通格選擇／候選、特殊格參照、適用範圍及證據。
- `strength`：初步分類、各觀察量、限制及候選狀態。
- `preferences`：分開的取用方案、沒有方案的原因、通關／調候註記。
- `comparison`：格局、強弱、用神方向各自比較舊 App 值；不可用一個 agree 代表整段一致。
- `sources`：課程日期及規則 ID；`limitations` 為本盤相關限制。

每個步驟有標題、結論、證據及限制。每項證據有穩定 ID、`kind`、柱位／藏干或互動來源、說明與課程日期。`kind` 分 `chart_fact`、`lesson_rule`、`engineering_proxy`、`model_reference`。

每個喜忌方案有：`ruleId`、`title`、`applicability`、`condition`、`useDirections`、`favorableDirections`、`unfavorableDirections`、`conditionalDirections`、`evidenceIds`、`rejections`、`sources`。方向含十神家族及換算後五行；不能把十神名稱放進五行欄位。

實作成熟度與結論狀態分開：來源映射和條件分支可以完成實作並通過測試，依工程近似形成的老師用神候選仍標 candidate。不可由單元測試通過把未知領域門檻升格成老師已驗證規則。

## 6. 第一步：取格局

### 普通格

- 從四柱重新取得日主、月支藏干及十神，不將 `直輸四柱分析` 當格名。
- 有唯一合格的月藏干透出者，列其格局與透干位置。
- 多個透干者保留全部候選；可顯示既有取格器的排序作 App 參照，但該工程排序不能宣稱老師已核准，課堂欄標「多候選」。
- 無合格透干者，按月令可取藏干順序列普通格及依據；建祿／陽刃顯示採用的月令判法，不以此鎖定強弱。
- 複用現有十神／藏干／格名映射；不要維護互相矛盾的第二份表。必要時將小型純函式移到共用位置，但不改舊輸出。

### 特殊格

首版把既有特殊格結果標為 `model_reference`，不是新的課派成格認證。強弱出現旺極／衰極，或無根且無可見印比，必須提示特殊格資格需審查；既有模型未命中也不能宣稱課派特殊格已被排除。

若已有特殊格參照或極端候選，普通扶抑方案只可顯示為「若按普通格論」的條件解，不得作唯一正式結論。專旺 07/08 與 09/02 取用順位分開顯示；從兒說明比劫例外，不沿用「所有從弱忌印比」作課派結論。

實作界線補充：為遵守「舊模型只供比較」及參照值獨立性，普通方案一律保留普通格適用條件；極端／無根的資格審查由命盤事實獨立觸發。既有特殊格參照只增加比較說明，不增刪或改寫課堂方案、強弱或命盤事實。

不新增從格、專旺、化氣的泛化成格閾值；兩神成象維持排列／通關說明及普通格參照。此限制是首版確定行為，不是留給實作者自行決定的缺項。

## 7. 第二步：強弱候選與證據

### 可計算事實

- `sameSeasonElement`：日主五行等於月支本氣五行。
- `sealInSeason`：月支本氣為生我五行；與同氣得時分欄。
- `supportStemCount`：年、月、時三干中印比數，排除日干本身。
- `supportBranchCount`：四支本氣中印比數。
- `roots`：各支全部藏干的同干／同五行根，保留層位；不能把沖後折算值當原始藏干。
- `pressureFamilies`：三個非日主天干及四支本氣中的食傷、財、官殺家族集合；藏干的出現另列，不冒稱不存在。

### 初步候選

延續現有 07/22 工程近似 `supportStemCount >= 2 OR supportBranchCount >= 2` 作可重現的「得勢暫估」，**明示是工程候選，不是老師數值定義**。不得改用量化總分決定本步。

與同氣得時、至少一支同五行根組成三項觀察：

- 三項且表層無剋洩耗：旺極候選，另列藏干反向力量與專旺資格檢查。
- 三項且表層有剋洩耗：旺候選。
- 兩項：強候選。
- 一項：弱候選。
- 零項且表層食傷、財、官殺三類全現：衰極候選。
- 零項但未三類全現：條件不足，不自動叫衰極。

最後一項修正只用於新三步流程；舊 07/22 註解若暫時仍有不同結果，明示為舊版候選或在畫面折疊，不能把它當新流程最終結論。

### 互動處理

首版不製造合沖扣分公式。由本命互動資料列出實際沖、合、會、刑及受影響位置；關係存在、模型判作合化、課堂根氣失效是三種不同證據。

遇到可能改變生扶或剋洩耗的互動，保留初判但將狀態標 conditional，附「互動後有效力量未定」及受影響證據。不得宣稱已把合沖效果完整重算，也不得把 unknown 當 false。

本步輸出候選與證據，第三步只讀本步狀態；舊量化偏強／偏弱僅供比較。

## 8. 第三步：條件式喜忌方案

### 生成原則

首版不以新增分數決定「印最多、官殺最重」。使用實際可見、當令、藏干和根氣位置，產生有來源的條件分支；「出現」不冒稱「主導」。

- 該問題家族在可見天干或支本氣出現，才提出其條件方案，附實際柱位。
- 只藏而不顯者列藏干證據，不稱顯露或主導。
- 方案可顯示「若印為本局主導問題，則……」；未判定主導時 `applicability=conditional`。
- 多方案不得按程式碼順序選第一條，不把不同方案的喜、忌合併。穩定排序僅供閱讀，不代表高低優先。
- 若無足夠證據支持細分方案，仍顯示普通扶抑方向與具體缺口，不輸出空白卡片或固定課堂故事。

### 普通格分支

| 課堂強弱候選 | 主導問題條件 | 用神方向 | 喜神方向 | 主要限制 |
| --- | --- | --- | --- | --- |
| 強／旺 | 印多妨害洩身 | 財制印 | 食傷生財 | 比劫制財、財無力、食傷受印制 |
| 強／旺 | 比劫多且官殺可制 | 官殺制比 | 財生官殺 | 食傷制所用殺、印反生身 |
| 強／旺 | 比劫多且食傷可洩 | 食傷洩比 | 財承接 | 印制食傷、承接不足 |
| 強／旺 | 財藏殺顯、有殺根 | 官殺候選 | 財生官殺 | 不代表殺已足以制身，與印多取財方案分開 |
| 強／旺 | 官藏財顯 | 財候選 | 食傷生財 | 地支財本氣也算顯露證據，不冒稱透干 |
| 弱 | 官殺剋身 | 印化殺扶身 | 比劫 | 財破印生殺、無通路 |
| 弱 | 食傷洩重 | 印制食傷扶身 | 比劫 | 印受制、食傷生財加重耗身 |
| 弱 | 財旺耗身 | 比劫分財 | 印 | 食傷生財、官殺制比、財破印 |

財、官殺等「可用」先列透干、本氣、同五行根及受制證據，不能僅有一個布林 hasWealth 就斷定可用。此首版仍是可追溯的條件方案，不宣稱有效力量已完成認證。

### 通關、病藥、調候

- 五組相剋／通關映射可確定計算，輸出候選路徑與實際節點；沒有中介就列缺少節點，存在也不稱通關已成功。
- 病藥先指明正在保護的方案及妨害作用，不反過來覆寫上游強弱。
- 冬／夏取排盤月支，不讀農曆月份數字。只顯示與扶抑一致、需承接或有衝突的條件說明，不輸出固定「冬用火」或「夏用水」。
- 非明確覆蓋的調候情境輸出未評估理由，不自動套用其他課例。

## 9. UI 與錯誤處理

CourseContentPanel 頂部改為三步本命分析；新增子元件 `LessonThreeStepPanel.vue` 可隔離呈現邏輯。原例列表移到「課堂命例補充」折疊區，保留原行為但不與新結論混列。

每步先顯示一行結果，再顯示關鍵理由；技術規則 ID、工程門檻和來源在展開內容中。用自然中文表示「候選」「有條件」「依據不足」，不把內部 enum 或 fixture 字樣堆在主標題。

普通格有多候選、強弱受互動影響、喜忌多方案都應正常呈現，不是錯誤頁。禁止用綠色「已驗證」表示只是程式執行過。

非法輸入沿用排盤入口驗證；對缺少新欄位、空集合、多個證據與長中文內容保持可讀。桌面及精簡分析頁共用同一資料，不新增後端請求或前端重新算五行。

## 10. 驗收與測試

測試先於實作，採失敗測試 → 最小實作 → 回歸。至少涵蓋：

1. 日期排盤和直輸同一四柱有相同核心三步結果。
2. 非課堂命例也執行三步；改一柱時事實與適用方案按新盤改變。
3. 精確課例一柱近似盤不命中舊註解，但仍有通用分析。
4. 比肩／劫財、正偏印、十神到五行映射與根氣層位正確。
5. 同氣得時與印當令分開；得勢邊界 1／2 清楚標工程近似。
6. 零項且只出現一種剋洩耗不標衰極；三類全現才列衰極候選。
7. 含藏干反向元素的旺極來源例，不宣稱完全沒有剋洩耗元素。
8. 合沖證據存在時保留 conditional，未刪根、未重複加扣分。
9. 第三步不依賴傳入的舊量化強弱；只改 App 參照值不應改課堂方案。
10. 財藏殺顯與官藏財顯使用不同證據；多方案不產生假優先序。
11. 同一元素跨方案可有不同角色，但單方案內矛盾需列條件而非靜默去重。
12. 特殊格參照或極端候選不無條件套普通扶抑；專旺兩課版本並存、從兒例外不漏。
13. 病藥先有保護對象；通關只有映射不自動稱成功；冬生不固定取火。
14. 不確定來源例不增加 fixture；來源命例與合成的結構測試盤分清標籤。
15. 序列化欄位與 TypeScript 一致；舊資料無新欄不崩潰；舊 `geJu`、量化及用神回歸不變。
16. 桌面／精簡版能讀完整三步、展開證據和多方案；不出現課程規則庫。

命例一致性用來發現缺口，不以硬編四柱答案提高通過數。首版若與老師來源結論不同，必須可見地列候選限制，不能聲稱完全重現老師判斷。

整體驗證執行 `cargo test --manifest-path src-tauri/Cargo.toml`、`npm run build`，以及本地 UI 檢查。執行前後記錄環境與結果，區分既有失敗及新回歸；無法驗證的項目明列，不用建置成功代替 UI 或規則驗證。
